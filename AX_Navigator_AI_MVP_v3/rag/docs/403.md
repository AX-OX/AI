## 207 장애 티켓 분류·배정

process_id=207. 목적: 반복 장애의 초기 분류·담당 팀 배정 초안을 만들어 대응 대기시간을 줄인다.
절차:
1. 장애 티켓 접수
2. 비밀값 제거
3. 유형·긴급도 초안 분류
4. 담당 팀 배정
5. 예외 티켓 이관
requires_approval=false. 정해진 예외는 담당자에게 이관한다.
예외 규칙: 보안사고·최고 심각도 장애·낮은 분류 확신은 온콜 담당자에게 즉시 이관한다. 운영 시스템 복구 명령은 실행하지 않는다.

## 208 코드 리뷰 보조

process_id=208. 목적: 승인된 기술 문서를 근거로 코드 변경의 검토 초안을 제공한다.
절차:
1. 변경 요청 수집
2. 승인된 기술·API 문서 검색
3. 정적 검사 결과 확인
4. 리뷰 의견 초안 작성
5. 개발자 최종 검토·승인
requires_approval=true. 사람의 최종 검토·승인 후 진행한다.
예외 규칙: 코드 병합과 배포는 개발자가 결정한다. 선행 과제 509의 문서 구축 완료 후 적용한다.

## 209 기술·API 문서 작성

process_id=209. 목적: 코드와 명세로 기술·API 문서 초안을 만들고 사람이 검토한 버전을 지식 기반으로 관리한다.
절차:
1. 변경 명세 수집
2. 기존 문서·코드 대조
3. API 문서 초안 작성
4. 개발자 검토·승인
5. 버전 게시
requires_approval=true. 사람의 최종 검토·승인 후 진행한다.
예외 규칙: 시크릿·고객 데이터는 문서에 넣지 않는다. 승인 전 문서는 리뷰 보조 지식 기반에 게시하지 않는다.
