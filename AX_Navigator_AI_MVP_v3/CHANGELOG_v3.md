# NoRole → v3 변경 이력

- 기존 NoRole 폴더를 보존하고 새 패키지로 생성했다.
- 4개 부서·12개 업무에서 인사·기획·개발 3개 부서·9개 업무로 변경. 2026-07~09 합성 지표 27건, 시스템 6개, 연결 17개, 솔루션 9개, 문서 8개·청크 34개.
- 회사는 직원 200명, AX 예산 3억 원으로 유지. 사용자 601·602는 원본 값과 BCrypt 해시를 그대로 보존. 역할 컬럼 없음.
- target_process_id·depends_on_solution_id, roadmap_items의 AX·Impact·Feasibility·3년 순편익 컬럼을 최신 계약 그대로 반영했다.
- 과제 목적 함수를 AX점수 합 최대로 변경하고 ROI·회수 기간·3년 순편익은 보조 지표로 이동했다. 새로운 정책 JSON과 검산 스크립트로 정답·fixture를 생성한다.
- 203 최종 인사평가 자동 판단은 제외. 508 코드 리뷰 보조는 509 승인형 기술 문서 구축에 의존한다. API 판정 두 사례, 사람 검토, 낮은 표준화 경고를 포함한다.
- 문서 벡터는 같은 PostgreSQL의 pgvector로 전환. legacy 적재 파일 대신 pgvector_import.jsonl·pgvector_ingest.py를 제공한다. RAG 2개 테이블을 별도 SQL로 분리해 전체 ax 16개·FK 27개다.
- 문서 원문 절차·승인·예외를 시드에서 생성해 불일치를 방지한다. 업무 매핑은 doc_mapping.json의 related_process_ids에 통합했다.
- 이미 역할이 없는 신규 DB를 생성하므로 기존 sql/02_migrate_remove_user_roles.sql은 포함하지 않는다.
- 시드와 명시 승인 fixture를 분리했고 SQLite는 미리보기용이다. 실제 DB 검증은 임시 PostgreSQL 17.10 + pgvector 0.8.1에서 실행했으며 목표 PostgreSQL 16은 미검증임을 기록한다.

## 합성 가정 설계·조정 근거

- 개발팀의 장애 분류·리뷰·문서 업무는 반복 처리 시간이 크고 API 연결이 있어 높은 효과·실현 가능성을 가정했다. 이 수치는 실제 기업 효과를 뜻하지 않는다.
- 리뷰 보조가 근거 문서를 필요로 하므로 같은 개발 부서의 문서 구축을 선행 과제로 설정했다.
- 단순 점수 상위 3개가 예산과 선행 제약을 위반하도록 초년도 비용 가정을 배치했다. 스크립트 전수 탐색으로 예산과 의존성 조건을 동시에 확인했다.
- 직원 규모를 고려해 온보딩은 월 5건, 건당 담당자·교육·안내 합산 30시간을 기준 가정으로 했다. 월별 변화는 절차 수행 시간에 반영한다. 모든 업무의 시간은 팀 전체 처리 시간이다.
- 기준 결과를 손으로 입력하지 않았다. 구축비·운영비·효과율·활동량은 시나리오 설계 입력이고 모든 출력 수치는 계산 스크립트에서 생성한다.

## 계약 변경 제안

없음. 두 계약 문서의 스키마·수식·API 이름을 유지했다. 명시되지 않은 표시 소수 자릿수와 점수 합산 기준은 README에 재현 규칙으로 명시했다. 추후 팀 합의로 표시 반올림 규칙을 공통 문서에 명문화하면 좋다.

## 서비스 연결 시 필요한 후속 작업

본 패키지는 데이터 산출물이다. 기존 Agent·Spring·RAG 로더는 이전 부서/정책/JSONL 경로를 참조하므로 최신 계약으로 별도 동기화해야 한다. 기존 compose 마운트나 운영 DB를 자동 변경하지 않았다. SQL/정답을 백엔드 담당자에게 전달하고 새로운 DB·색인에서 통합한다.
