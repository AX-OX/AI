# 후보 발굴 입력 크기 수정

- 오류: 업로드 PDF 분석에서 `DISCOVER_CONTEXT_LIMIT: 26129 characters exceeds 24000` 발생.
- 성숙도 결과 저장은 성공했으며 이후 discover의 LLM 호출 전 입력 검사에서 실패했다.
- 원인: 전체 `evidence`와 후보용 `business_evidence`에 같은 문서 본문을 중복 포함했다.
- 수정: 원문·근거 ID·후보 쌍은 보존하면서 전체 evidence의 중복 전달을 제거했다. 추적의 evidenceCount는 실제 후보 근거 수를 사용한다.
- 동일 실패 입력: 26,129자 → 17,015자, 청크 10개·후보 9개 유지.
- 추가 설정 변경: 사용자 요청에 따라 discover 한도를 24,000자에서 28,000자로 확장했다. 문자 수 기준이며 다른 단계의 제한은 변경하지 않았다. JSON·근거 원문을 잘라 통과시키지 않는다.
- 회귀: 중복 제거·허용 근거 ID·실제 Reasoner 경로·24,001/28,000자 허용·28,001자 거부를 검증한다.
- 실제 실패 체크포인트의 입력으로 OpenAI 후보 발굴 → Spring 계산 → 로드맵 생성까지 확인했다. 선정은 (226,507), (227,508), (228,509), AX점수 합 265, 비용 295,000,000원이었다. 실패 작업의 상태와 저장 결과를 덮어쓰지는 않았다.
- BE·FE 소스 변경 없음. 이 수정만으로 대용량 문서 전체를 항상 수용하는 것은 아니며 28,000자 초과 시 기존 명시적 오류를 유지한다.
